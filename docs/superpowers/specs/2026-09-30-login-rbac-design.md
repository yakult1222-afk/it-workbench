# IT 工作台登录与角色权限设计

- 日期：2026-09-30
- 分支：`feat/login`
- 状态：已确认，待实施

## 1. 目标

在现有 IT 工作台上增加登录、账号管理、角色管理和任务归属能力，并调整任务、首页统计和日报的数据范围。

完成后应满足：

- 未登录用户不能访问业务页面和接口。
- 人员管理指登录账号管理。
- 一个账号只绑定一个角色，一个角色拥有多个权限。
- 角色权限由超级管理员配置。
- 任务列表支持归属人字段和归属人筛选。
- 普通用户只能查看和管理自己的任务。
- 拥有全部任务权限的账号可以查看全部任务，并按归属人筛选。
- 日报始终只汇总当前登录人当天的任务。
- 现有任务全部迁移到账号 `qinghuan`（姓名：清欢）。
- 系统提供一个超级管理员账号 `admin`。
- 初始账号首次登录不强制修改密码。

## 2. 非目标

本次不实现：

- 多角色账号。
- 公开注册、短信验证码、邮箱找回密码。
- OAuth、企业微信、钉钉等第三方登录。
- 登录审计、操作日志和上线审批流。
- 刷新令牌和多设备会话管理。
- 员工档案、组织架构、部门或岗位管理。

## 3. 权限模型

### 3.1 权限清单

| 权限编码 | 权限名称 | 说明 |
|---|---|---|
| `task:self:view` | 查看本人任务 | 查看本人任务、本人首页统计 |
| `task:self:manage` | 管理本人任务 | 新增、修改、删除本人任务 |
| `task:view:all` | 查看全部任务 | 查看全部任务及全部任务的首页统计 |
| `task:manage:all` | 管理全部任务 | 新增、修改、删除全部任务，并指定归属人 |
| `user:manage` | 人员管理 | 新增账号、编辑账号、启停账号、重置密码 |
| `role:manage` | 角色管理 | 新增、编辑、删除角色，配置角色权限 |

权限依赖规则：

- `task:self:manage` 依赖 `task:self:view`。
- `task:manage:all` 依赖 `task:view:all`。
- 角色保存时后端校验依赖关系并拒绝无效组合。
- 超级管理员拥有全部权限。

### 3.2 内置角色

| 角色编码 | 角色名称 | 权限 |
|---|---|---|
| `SUPER_ADMIN` | 超级管理员 | 全部权限 |
| `USER` | 普通用户 | `task:self:view`、`task:self:manage` |

约束：

- `SUPER_ADMIN` 不可删除，编码不可修改，权限固定为全部权限。
- 已绑定账号的角色不可删除。
- 自定义角色的编码全局唯一。
- 超级管理员角色不能通过角色管理接口移除权限。

### 3.3 初始化账号

| 用户名 | 姓名 | 角色 | 初始密码 |
|---|---|---|---|
| `qinghuan` | 清欢 | `USER` | `Qinghuan@123456` |
| `admin` | 超级管理员 | `SUPER_ADMIN` | `Admin@123456` |

初始密码只用于首次建库或迁移，数据库中保存 BCrypt 哈希。首次登录不强制修改密码。

密码规则：长度为 8–64 位，至少包含一个字母和一个数字，不能为纯空白或与用户名相同。

## 4. 数据模型

### 4.1 新增表

`sys_role`

- `id`：主键
- `code`：角色编码，唯一
- `name`：角色名称
- `description`：说明
- `built_in`：是否内置
- `created_at`、`updated_at`

`sys_permission`

- `id`：主键
- `code`：权限编码，唯一
- `name`：权限名称
- `description`：说明

`sys_role_permission`

- `role_id`：角色 ID
- `permission_id`：权限 ID
- `(role_id, permission_id)`：联合主键

`sys_user`

- `id`：主键
- `username`：登录用户名，唯一
- `password_hash`：BCrypt 密码哈希
- `display_name`：姓名
- `role_id`：角色 ID，一个账号只能绑定一个角色
- `enabled`：启用状态
- `created_at`、`updated_at`

### 4.2 修改 `task`

新增字段：

- `owner_id BIGINT NOT NULL`：任务归属账号，关联 `sys_user.id`

新增索引：

- `idx_task_owner_date(owner_id, task_date)`
- `idx_task_owner_status(owner_id, status)`

外键：

- `task.owner_id -> sys_user.id`，删除策略为 `RESTRICT`

账号不物理删除，只允许禁用，以保证历史任务归属不会丢失。

## 5. 数据迁移

### 5.1 新环境

更新 `backend/sql/init.sql`，直接创建最终表结构、全部权限、两个内置角色以及 `qinghuan`、`admin` 账号。

### 5.2 已有环境

新增一次性迁移脚本，执行顺序：

1. 备份现有数据库。
2. 创建 `sys_role`、`sys_permission`、`sys_role_permission`、`sys_user`。
3. 写入全部权限和两个内置角色。
4. 创建 `qinghuan` 和 `admin`，密码保存为 BCrypt 哈希。
5. 给 `task` 增加可空的 `owner_id`。
6. 将所有旧任务的 `owner_id` 更新为 `qinghuan.id`。
7. 校验旧任务数量不变。
8. 将 `owner_id` 改为 `NOT NULL`。
9. 创建索引和外键。
10. 验证全部旧任务均归属于 `qinghuan`。

迁移前必须使用 `mysqldump` 备份，迁移脚本按一次性执行设计，并在 README 中写明执行步骤。

## 6. 后端设计

### 6.1 技术组件

采用 Spring Security + JWT + BCrypt：

- Spring Security 负责认证过滤器链、接口权限和方法权限。
- JWT 负责无状态登录态。
- BCrypt 负责密码哈希。
- MyBatis-Plus 负责数据访问。
- 现有统一响应结构继续使用，并补充正确的 HTTP `401`、`403`、`409`、`400` 状态码。

### 6.2 核心组件

- `SecurityConfig`：过滤器链、无状态会话、公开登录接口、其它接口认证。
- `JwtService`：生成和解析 JWT。
- `JwtAuthenticationFilter`：解析 Bearer Token 并建立认证上下文。
- `LoginUser`：保存账号 ID、用户名、姓名、角色和权限集合。
- `CurrentUserService`：从认证上下文读取当前账号。
- `AuthService`：登录校验和当前用户信息。
- `UserService`：账号分页、增改、启停、重置密码。
- `RoleService`：角色和权限管理。
- `TaskScopeService`：统一计算任务数据范围并执行归属校验。
- `TaskService`：按数据范围查询、新增、修改和删除任务。
- `StatsService`：按当前账号的数据范围计算首页统计。
- `DailySummaryService`：只查询并汇总当前账号当天任务。

### 6.3 认证接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/auth/login` | 用户名密码登录，返回 JWT、账号、角色、权限 | 公开 |
| GET | `/api/auth/me` | 获取当前登录账号 | 已登录 |
| POST | `/api/auth/logout` | 无状态退出响应，前端删除令牌 | 已登录 |

JWT 默认有效期 8 小时，通过 `JWT_EXPIRE_HOURS` 配置。签名密钥通过 `JWT_SECRET` 配置，生产环境禁止使用默认值。

### 6.4 账号接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/users` | 分页查询，支持用户名、姓名、状态、角色筛选 | `user:manage` |
| GET | `/api/users/options` | 获取任务归属人下拉选项 | `task:view:all` |
| POST | `/api/users` | 新增账号 | `user:manage` |
| PUT | `/api/users/{id}` | 编辑账号 | `user:manage` |
| PATCH | `/api/users/{id}/status` | 启用或禁用账号 | `user:manage` |
| POST | `/api/users/{id}/reset-password` | 重置密码 | `user:manage` |

约束：

- 用户名唯一。
- 密码只在新增和重置时提交。
- 响应永不包含密码哈希。
- 当前账号不能禁用自己。
- 不能禁用最后一个可用的超级管理员。
- 不能将最后一个可用的超级管理员改为其它角色。
- 账号不提供物理删除接口。

### 6.5 角色接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/roles` | 查询角色列表 | `role:manage` |
| GET | `/api/roles/options` | 查询启用角色选项，用于账号编辑 | `user:manage` 或 `role:manage` |
| GET | `/api/roles/{id}` | 查询角色详情和权限 | `role:manage` |
| POST | `/api/roles` | 新增角色 | `role:manage` |
| PUT | `/api/roles/{id}` | 编辑角色和权限 | `role:manage` |
| DELETE | `/api/roles/{id}` | 删除未被账号使用的角色 | `role:manage` |
| GET | `/api/permissions` | 查询权限清单 | `role:manage` |

### 6.6 任务和统计接口

`GET /api/tasks` 新增可选参数 `ownerId`。

数据规则：

- 只有 `task:self:view`：强制查询当前账号任务，忽略客户端传入的 `ownerId`。
- 有 `task:view:all`：默认查询全部任务；传入 `ownerId` 时按归属人筛选。
- `GET /api/tasks/{id}`、修改、删除同样执行数据范围校验。
- 没有 `task:manage:all` 时，新增和修改强制使用当前账号作为归属人。
- 有 `task:manage:all` 时，可以指定任务归属人。
- `GET /api/stats/today` 跟随任务查看范围：个人权限查询个人数据，全部权限查询全部数据。
- `GET /api/daily-summary` 需要 `task:self:view`，无论其它权限如何，只查询当前登录人当天的任务。

### 6.7 安全配置

- JWT 校验失败或过期返回 `401`。
- 已登录但权限不足返回 `403`。
- 登录失败统一返回“用户名或密码错误”。
- CORS 从任意来源收紧为可配置白名单。
- 生产环境必须显式配置 `JWT_SECRET`。
- 超管角色、最后一个超管账号等关键约束不能只依赖前端判断。

## 7. 前端设计

### 7.1 登录和登录态

新增 `LoginView`，提供用户名和密码登录。登录成功后：

- 保存 JWT 和当前账号信息到 `localStorage`。
- Axios 请求自动添加 `Authorization: Bearer <token>`。
- 收到 `401` 时清理登录态并跳转 `/login`。
- 收到 `403` 时保留登录态并提示无权限。

新增轻量 `auth` 状态模块，不引入 Pinia。该模块负责：

- 当前账号和权限缓存。
- `isLoggedIn()`。
- `hasPermission(code)`。
- 登录、刷新当前账号和退出。

### 7.2 路由和导航

路由：

| 路径 | 页面 | 要求 |
|---|---|---|
| `/login` | 登录页 | 公开 |
| `/` | 首页 | 已登录 |
| `/tasks` | 任务列表 | 已登录 |
| `/users` | 人员管理 | `user:manage` |
| `/roles` | 角色管理 | `role:manage` |

顶部导航根据权限显示“人员管理”和“角色管理”。右侧显示当前姓名、角色和退出按钮。登录页不显示业务导航和页脚。

### 7.3 任务列表

- 表格新增“归属人”列。
- 筛选区新增“归属人”下拉框。
- 只有 `task:view:all` 时加载和显示归属人筛选。
- 新增/编辑弹窗在 `task:manage:all` 时显示归属人选择。
- 普通用户提交任务时由后端固定归属人，前端不暴露该字段。
- 列表展示每个任务当前归属人的姓名。

### 7.4 人员管理

页面包含：

- 用户名、姓名、状态、角色筛选。
- 账号分页列表。
- 新增账号。
- 编辑姓名、角色和启用状态。
- 启用/禁用账号。
- 重置密码。

新增账号必须填写用户名、姓名、角色和初始密码。编辑账号不回显密码。

### 7.5 角色管理

页面包含：

- 角色列表和说明。
- 新增角色：编码、名称、说明、权限。
- 编辑自定义角色及权限。
- 删除未被账号使用的自定义角色。
- `SUPER_ADMIN` 显示锁定标识，不能编辑权限或删除。

### 7.6 首页和日报

- 首页完成率和任务概览使用后端返回的数据范围。
- 页面明确显示统计范围是“本人”还是“全部人员”。
- 日报弹窗始终标注“当前登录人今日任务”。
- 日报内容只基于当前登录人的任务。

## 8. 错误处理

- `400`：参数校验失败、权限组合无效、密码不符合要求。
- `401`：未登录、令牌无效或过期。
- `403`：账号被禁用或权限不足。
- `404`：账号、角色、任务或权限不存在。
- `409`：用户名重复、角色编码重复、角色仍被账号使用、违反最后一个超管约束。
- `500`：未预期服务异常，保留服务端日志，不向前端泄露堆栈。

前端对 `401`、`403` 和业务错误使用统一提示；表单接口错误保留在弹窗内展示。

## 9. 测试策略

### 9.1 后端

- 认证测试：正确密码、错误密码、禁用账号、无效 JWT、过期 JWT。
- 接口安全测试：未登录访问业务接口返回 `401`，无权限返回 `403`。
- 账号测试：新增、编辑、启停、重置密码、重复用户名、不能禁用自己、不能禁用最后一个超管、不能修改最后一个超管的角色。
- 角色测试：权限依赖、内置角色不可删除、角色被使用不可删除、权限保存、角色选项接口访问控制。
- 任务范围测试：普通用户只能查看和修改自己的任务，伪造 `ownerId` 无效。
- 全部任务权限测试：管理员默认查看全部任务，并能按归属人筛选。
- 日报测试：始终只汇总当前登录人的当天任务。
- 统计测试：个人权限统计个人任务，全部权限统计全部任务。
- 迁移验证：迁移前后任务数量一致，全部旧任务归属于 `qinghuan`。

### 9.2 前端

- 执行 `npm run build`，确保生产构建通过。
- 浏览器验证登录、退出、刷新后保持登录态、受保护路由和无权限提示。
- 验证人员管理、角色管理、归属人筛选和任务新增/编辑。
- 验证普通用户看不到人员、角色和全部任务入口。
- 验证管理员首页统计和日报范围符合设计。

### 9.3 回归

- 运行完整 Maven 测试。
- 执行 SQL 迁移后验证任务数量。
- 回归首页、任务 CRUD、统计、硬件资讯和日报。
- 验证一体化打包后仍可通过 `8080` 同时访问页面和 API。

## 10. 验收标准

- 未登录访问业务页面时自动跳转登录页。
- 使用 `admin / Admin@123456` 可以登录。
- 使用 `qinghuan / Qinghuan@123456` 可以登录。
- 现有任务全部显示归属人为“清欢”。
- 普通用户只能看到自己的任务，且无法通过参数读取他人数据。
- 管理员可以查看全部任务并按归属人筛选。
- 人员管理支持新增、编辑、启停和重置密码。
- 角色管理支持自定义权限，并保护内置超级管理员角色。
- 日报只汇总当前登录人当天任务。
- 后端测试、前端构建和浏览器回归验证通过。
